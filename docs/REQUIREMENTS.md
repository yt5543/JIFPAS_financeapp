# 要件定義 — ミエルカ（Mieruka）

> 資産と未来を、見える化する。
> JIFPAS 織田耕平氏との協業構想（2026-08-05 MTG）をもとに、**織田氏に見せるデモ版（MVP）** を最短で作るための要件定義。
> ★ = 未確定・要確認。⚠ = 法務リスク（本開発では通知のみ、作業はそのまま進める）。

---

## 0. 名称・位置づけ

| 項目 | 内容 |
|---|---|
| アプリ名 | **ミエルカ（Mieruka）** — 「見える化」から。音声メモの「ミベルカー」に最も近い名前として採用。仮称扱いで変更可 |
| タグライン | 資産と未来を、見える化する。 |
| 位置づけ | 金融を学ぶコミュニティ（サブスク）の**フロントになる無料ツール**。オンライン利用 |
| 立場 | **どの金融機関・商品にも属さない中立ツール**。商品の推奨・勧誘は一切しない（議事録 決定事項 #2） |
| 一次目的 | 自分の資産の現状（BS）を知る → 将来目標とのギャップに気づく → 「考える癖」がつく |
| 二次目的 | 高利回りが必要と分かった人が、JIFPAS側の相談導線（海外IFA／投資顧問）に自然に到達する（決定事項 #3） |

## 1. ターゲットユーザーと課題

- **主ターゲット**: 30〜50代の会社員・個人事業主。NISAは「いいと聞いたから」で始めており、目標を立てて運用する習慣がない層
- **課題**（織田氏の認識）
  - 家計簿アプリはPL（毎月の収支）だけで、BS（資産全体）を見る道具がない
  - A社・B社・C社に分散した証券、不動産、保険、現金、現物（金）を統合して見る道具がない
  - リスク許容度は生活水準・家族構成・居住地で全く違うのに「みんな同じ運用」になっている
  - 「今どういう状況で、何をすべきか」が一目で分からない

## 2. スコープ

### フェーズ1（今回のデモ版 = MVP）
資産管理・見える化に徹する。**入力は全て手動**（口座連携なし）。

| # | 機能 | 優先度 |
|---|---|---|
| F1 | 資産の登録・編集・削除（BS管理） | 必須 |
| F2 | 資産ごとの「運用対象／対象外」区分と、自宅不動産の除外 | 必須 |
| F3 | 資産ごとの想定利回りの手入力（例: この商品は5%想定） | 必須 |
| F4 | 目標設定（目標年齢・目標金額・毎月積立額） | 必須 |
| F5 | 必要利回りの逆算（積立を加味） | 必須 |
| F6 | ダッシュボード（総資産／運用可能資産／目標達成度／必要利回り／グラフ） | 必須 |
| F7 | 「このままだと目標年齢でいくらか」の将来予測（現状の加重平均利回りで試算） | 必須 |
| F8 | 非現実的な必要利回り（15%以上）への警告と見直し導線（積立増・目標年齢延長・目標額見直し） | 必須 |
| F9 | 感度分析スライダー（積立額／目標年齢を動かすと必要利回りがどう変わるか） | 推奨 |
| F10 | 年次レビュー用スナップショット保存と前回比較 | 推奨 |
| F11 | デモ用サンプルデータ読込（議事録の試算例: 30歳／40歳／50歳スタート） | 必須（デモ用） |
| F12 | データはブラウザ（localStorage）に保存。JSONエクスポート／インポート | 推奨 |

### フェーズ2（デモには「プレビュー」として最小限だけ載せる）
| # | 機能 |
|---|---|
| P1 | 商品マスタ（管理者が裏側で追加・更新するDB）。デモではJSONのモックデータ |
| P2 | 必要利回りに近い商品の**参考表示**（推奨ではない旨を明示）⚠ |
| P3 | 商品を選ぶと「見えないリスク」を一覧表示（発行体リスク／為替／流動性／元本保護の有無／判定スタイル 等）。数値以外（バッジ・文章）でも見せる |
| P4 | 高利回りが必要な人向けの「専門家に相談する」導線（JIFPAS側IFAへ）⚠ |
| P5 | 商品の組み合わせによるリスクの相殺・変化の可視化（議事録 §6） |
| P6 | リスク許容度の把握（アンケートは参考値に留める） |

### 非目標（やらないこと）
- 金融機関API連携・自動残高取得
- 商品の購入・口座開設などの取引機能
- 不動産の自動査定、保険の解約返戻金計算
- 法人向け「未来会計」（議事録 §7）— 別プロダクトとして将来検討
- ユーザー認証・サーバー保存（デモ版では不要。本番化時に追加）

## 3. 画面構成（MVP）

```
/            ダッシュボード（サマリー・グラフ・警告・次にやること）
/assets      資産一覧・追加・編集
/goal        目標設定（年齢・目標額・積立）＋感度分析
/review      年次レビュー（スナップショット保存・前回比較）
/products    参考商品と見えないリスク（フェーズ2プレビュー、βラベル）
/settings    データのエクスポート／インポート／サンプル読込／全消去
```

### 3.1 ダッシュボード
- 上段カード: 総資産／運用可能資産／運用対象外資産／目標達成率
- 中段: 「必要利回り **X.X%**／年」と「現状のまま（加重平均利回り Y.Y%）だと目標年齢で **Z 万円**」を並べて表示
- グラフ: 資産構成ドーナツ（カテゴリ別）、目標までの成長曲線（現状ペース vs 必要ペース）
- 警告: 必要利回りが 8%以上で注意、15%以上で「非現実的」表示＋見直し提案ボタン
- 「次にやること」: 資産未登録／目標未設定／年次レビュー期限（前回スナップショットから1年）を案内

### 3.2 資産一覧
- カテゴリ: 現金・預金／有価証券（株・投信・債券等）／不動産／保険／その他（金・暗号資産等）
- 項目: 名称、カテゴリ、評価額（円）、想定利回り（%／年、任意）、運用対象フラグ、メモ
- 不動産のみ追加項目: 用途（自宅／賃貸・貸出可能／その他）。**自宅は運用対象外に自動設定**（手動で上書き可）
- 一覧は運用対象／対象外でグルーピングし、それぞれ小計を表示

### 3.3 目標設定
- 入力: 現在の年齢、目標年齢（初期値65）、目標金額、毎月の積立額（初期値0）
- 出力（即時再計算）: 必要利回り、達成に必要な元手（現在利回り前提）、現状ペースでの到達額
- 感度スライダー: 積立額（0〜30万円）、目標年齢（現在年齢+1〜80）

### 3.4 年次レビュー
- 「今の状態を保存」ボタンで日付付きスナップショット（総資産・運用資産・必要利回り・資産内訳）
- 前回との差分表示（増減額・増減率・必要利回りの変化）と「予定より上振れ／下振れ」判定

### 3.5 参考商品（β）
- 冒頭に固定表示: 「本画面は参考情報の提示であり、特定商品の推奨・勧誘ではありません」⚠
- 必要利回りを基準に、想定利回りが近い順に商品カードを表示（モックデータ）
- カードを開くと: 基本情報／リスク一覧（バッジ＋説明文）／「この商品が向かない人」
- 「専門家に相談する」ボタン（デモではダミーリンク）

## 4. 計算仕様

記号: 現在の運用可能資産 `P`、毎月積立 `m`、年数 `n = 目標年齢 − 現在年齢`、目標金額 `G`、年利 `r`。

- **利回りの定義**: 年複利の実効利回り（いわゆる年利回り・CAGR）。積立の月利は `i = (1+r)^(1/12) − 1` で年複利と整合させる
- **将来価値**（積立は月末）: `FV(r) = P·(1+r)^n + m·[((1+i)^(12n) − 1) / i]`（r=0 のとき `P + 12nm`）
- **必要利回り**: `FV(r) = G` を満たす r を二分法で求める（探索範囲 0〜100%、許容誤差 1e-9）
- **現状ペースの到達額**: 運用対象資産の評価額加重平均利回り `r̄` を使い `FV(r̄)`
- **境界**: `n ≤ 0` → エラー表示／`FV(0) ≥ G` → 必要利回り 0%（すでに達成可能）／`P = 0 かつ m = 0` → 達成不能
- **必要利回りの評価**: 4%未満=無理なく／4〜8%=分散投資で現実的／8〜15%=高リスクが必要／**15%以上=非現実的（警告＋見直し導線）**
- **検算データ**（議事録 §3、元手1,000万円→65歳で1億円）: 30歳=6.80%、40歳=9.65%（議事録の6.8%／9.7%と一致）。
  **★訂正: 50歳スタートは議事録では「約25%」だが、正しくは 10^(1/15)−1 = 約16.6%**（口頭概算の誤り。16.6%でも非現実的な水準である結論は変わらない）。織田氏に見せる前に一言添えること

## 5. 非機能要件

| 項目 | 内容 |
|---|---|
| 対応端末 | スマホ優先のレスポンシブ（織田氏へのデモはPC＋スマホ両方を想定） |
| 保存 | localStorage。サーバー送信なし（デモ段階では個人情報を一切外部に出さない） |
| 性能 | 全計算はクライアント側で即時（100ms以内） |
| 表記 | 日本語、金額は「万円」併記、利回りは小数1桁 |
| アクセシビリティ | 色だけに依存しない警告表示（アイコン＋文言） |

## 6. 技術スタック（選定理由つき）

| 層 | 選定 | 理由 |
|---|---|---|
| フロント | **Vite + React 18 + TypeScript** | 最速でSPAを組める。型で計算ロジックの事故を防ぐ |
| スタイル | **Tailwind CSS** | デザイン工数を最小化しつつスマホ対応 |
| グラフ | **Recharts** | ドーナツ・折れ線がすぐ出せる |
| 状態・保存 | **Zustand（persist / localStorage）** | バックエンド不要でデモが成立 |
| テスト | **Vitest** | 計算ロジック（必要利回り逆算）をユニットテストで担保 |
| デプロイ | **Cloudflare Pages** | 自社の既存運用（wrangler）と同じ。`--branch main` 必須（自社KNOWLEDGE参照） |
| フェーズ2 API | Hono on Cloudflare Workers + D1 | 商品マスタの管理画面・APIを同じCloudflare内で追加できる |
| 認証（本番化時） | Cloudflare Access または Supabase Auth | デモでは不要 |

## 7. ⚠ 法務リスク一覧（通知のみ・作業は続行）

| # | リスク | 本アプリでの回避方針 |
|---|---|---|
| L1 | 商品の「推奨」表示が投資助言（金商法・投資助言業）に該当する可能性 | 「参考情報」「推奨ではない」を常時表示。並び順は利回り近似のみで、優劣・おすすめ表現をしない |
| L2 | 無登録の海外金融商品を国内で広く紹介すると勧誘行為とみなされる可能性 | デモ商品はモック。実商品掲載時はJIFPAS側で掲載可否を判断。相談導線はJIFPAS側IFAへの「問い合わせ」に留める |
| L3 | 「年◯%で増えます」等の将来予測表示が断定的判断の提供と誤解される | 全ての将来値に「試算」「保証しない」注記。ユーザー入力の想定利回りに基づく旨を明示 |
| L4 | 個人の資産情報の取り扱い（個人情報保護） | デモ版はlocalStorageのみ。本番化時にプライバシーポリシー・サーバー保存設計を別途 |
| L5 | ★法務確認未実施（議事録 §3 合意事項） | 本番公開前に弁護士確認（金商法・景表法）を実施 |

## 8. 契約・座組（参考の一案・判断は保留でOK）

- **段階契約を推奨**: ①デモ版＝検証フェーズ（低額固定 or 持ち出し）→ ②本開発＝開発費＋**コミュニティ収益のレベニューシェア**
- **IP（著作権）は山本側が保持し、JIFPASに利用許諾**する形が、「中立ツール」というブランド価値を守りやすい（JIFPASブランドを前面に出すと中立性が薄れる）
- 商品マスタの内容・掲載判断はJIFPAS側の責任範囲、アプリの計算・表示は山本側の責任範囲、と切り分けておくとL1〜L2のリスク分担が明確
